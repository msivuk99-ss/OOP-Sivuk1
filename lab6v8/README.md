## 1. Короткий опис реалізованого інтерфейсу та абстрактного класу

* **Інтерфейс `IParser<T>`**:
  * Визначає контракт із методом `T Parse(string input)`.
  * **`DateParser`**: Клас-реалізація інтерфейсу для витягування дати з рядка.
  * **`TimeParser`**: Клас-реалізація інтерфейсу для витягування часу з рядка.

* **Абстрактний клас `Renderer`**:
  * Визначає контракт для відображення документів через абстрактні методи `RenderHeader()` та `RenderBody()`.
  * Містить конкретний базовий метод `RenderFooter()`, який використовує спільну логіку для всіх нащадків.
  * **`HtmlRenderer`**: Перевизначає відображення заголову та тіла у форматі HTML-тегів.
  * **`MarkdownRenderer`**: Перевизначає відображення у форматі Markdown-розмітки.

## Контрольні запитання

1. **У чому полягає основна відмінність між абстрактним класом та інтерфейсом?**  
   Абстрактний клас описує сутність ("чимось є" — *is-a*) і може містити реалізовані методи та стан (поля), а інтерфейс описує поведінку ("щось вміє робити" — *can-do*) і визначає лише контракт без стану об'єкта.

2. **Коли доцільно використовувати абстрактний клас, а коли - інтерфейс? Наведіть приклади.**  
   * **Абстрактний клас** — коли є спільна логіка або стан для тісно пов'язаних класів (наприклад, `Renderer` зі спільним методом `RenderFooter()`).  
   * **Інтерфейс** — коли треба додати однакову поведінку різним, не пов'язаним між собою класам (наприклад, `IParser<T>`).

3. **Чи може клас успадковувати від кількох абстрактних класів? А реалізовувати кілька інтерфейсів?**  
   Клас **не може** успадковувати більше одного абстрактного класу (в C# немає множинного успадкування класів), але **може** реалізовувати скільки завгодно інтерфейсів.

4. **Як абстрактні класи та інтерфейси сприяють поліморфізму та гнучкості архітектури?**  
   Вони дозволяють будувати програму на основі контрактів (абстракцій), а не конкретних класів. Завдяки цьому можна легко додавати нові класи-реалізації без переписання існуючого коду.
