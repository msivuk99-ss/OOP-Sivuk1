# Лабораторна робота №5: Поліморфізм: динамічне зв'язування та перевизначення методів

**Тема:** Поліморфізм: динамічне зв'язування та перевизначення методів.  
**Мета:** Навчитися реалізовувати поліморфну поведінку за допомогою віртуальних методів та їх перевизначення, а також агрегувати результати поліморфних викликів.  
**Варіант:** 8 (Поліморфні банківські операції: Transaction → Deposit, Withdrawal, Transfer)  

---

## 1. Короткий опис реалізованої іерархії класів

* **`Transaction` (базовий клас)**:
  * Властивість: `Amount` (сума транзакції).
  * Конструктор для ініціалізації суми.
  * Віртуальний метод `Execute()` для виконання банківської операції.

* **`Deposit` (похідний клас — поповнення)**:
  * Властивість: `DestinationAccount` (номер рахунку призначення).
  * Конструктор із викликом `base(amount)`.
  * Перевизначений метод `Execute()` (`override`).

* **`Withdrawal` (похідний клас — зняття)**:
  * Властивість: `SourceAccount` (номер рахунку списання).
  * Конструктор із викликом `base(amount)`.
  * Перевизначений метод `Execute()` (`override`).

* **`Transfer` (похідний клас — переказ)**:
  * Властивості: `FromAccount`, `ToAccount` (рахунки відправника та отримувача).
  * Конструктор із викликом `base(amount)`.
  * Перевизначений метод `Execute()` (`override`).

## Контрольні запитання
1. Що таке поліморфізм і як він реалізується в C# за допомогою virtual та override?

Поліморфізм — це здатність об'єктів різних класів обробляти однакові виклики методів по-різному. У C# він реалізується шляхом позначення методу базового класу ключовим словом virtual, а методу похідного класу — override.

2. Поясніть поняття динамічного зв'язування. Чим воно відрізняється від статичного?

Динамічне зв'язування (Late Binding) — це визначення того, яка саме реалізація методу викликається, під час виконання програми (Runtime) на основі фактичного типу об'єкта. Статичне зв'язування (Early Binding) відбувається під час компіляції (Compile time) на основі типу посилання.

3. Наведіть приклад, як поліморфізм дозволяє писати більш гнучкий та розширюваний код.

Поліморфізм дозволяє працювати з об'єктами через інтерфейс базового класу. Якщо додати новий тип транзакції (наприклад, Payment), код у Main (обхід колекції та підрахунок суми) не зміниться й виконуватиметься коректно без редагування існуючої логіки.

4. Які переваги дає використання колекцій базових типів для роботи з поліморфними об'єктами?

Це дозволяє зберігати різні похідні типи в одній уніфікованій структурі даних (наприклад, List<Transaction>), обробляти їх в одному циклі та проводити загальну агрегацію даних (сумування, фільтрацію, розрахунки) без явного приведення типів.
