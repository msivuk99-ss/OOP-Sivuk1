# Лабораторна робота №3: Життєвий цикл об'єкта та керування ресурсами
Варіант 8: Клас `TemporaryFile`

## Опис проєкту
Проєкт демонструє роботу з некерованими ресурсами (імітація тимчасового файла) та реалізацію патерну `Dispose` з інтерфейсом `IDisposable`.

## Реалізовані сценарії в Main:
1. Оператор `using`: Автоматичний виклик `Dispose()` при виході з блоку.
2. Явний виклик `Dispose()`: Ручне звільнення ресурсів після закінчення роботи з об'єктом.
3. Неявне звільнення через GC: Об'єкт залишається без посилань, після чого примусово викликаються `GC.Collect()` та `GC.WaitForPendingFinalizers()` для виклику деструктора `~TemporaryFile()`.

## Висновок
- Використання `using` є найбезпечнішим способом керування ресурсами, оскільки гарантує виклик `Dispose()` навіть при виникненні винятків.
- Явний виклик `Dispose()` дозволяє звільнити ресурси одразу після використання, не чекаючи збирача сміття.
- Деструктор є лише страховим механізмом: він викликається Garbage Collector у невідомий момент часу, тому покладатися лише на нього для звільнення важливих ресурсів не рекомендується.

## Контрольні запитання
1. Життєвий цикл об'єкта в .NET охоплює чотири етапи: виділення пам'яті в купі (heap) через new, використання об'єкта в коді, позначення об'єкта як непридатного після втрати всіх посилань та звільнення пам'яті збирачем сміття (GC) із можливим викликом деструктора.
2. Керовані ресурси (пам'ять для .NET-об'єктів) очищаються збирачем сміття повністю автоматично. Некеровані ресурси (файли, мережеві сокети, дескриптори ОС) знаходяться поза контролем .NET, тому вимагають ручного звільнення через метод Dispose().
3. Інтерфейс IDisposable надає єдиний стандартний метод Dispose() для явного та детермінованого звільнення некерованих ресурсів одразу, як тільки об'єкт стає непотрібним, не чекаючи спрацьовування збирача сміття.
4. Оператор using створює за кулісами блок try-finally, що гарантує виклик метода Dispose() при виході з блоку, навіть якщо під час виконання виникла помилка або виняток (Exception).
5. Виклик GC.SuppressFinalize(this) повідомляє збирачу сміття, що об'єкт вже самостійно очистив свої ресурси і його деструктор викликати більше не потрібно, що економить ресурси процесора та прискорює очищення пам'яті.
6. В деструкторі передається Dispose(false), щоб звільнити виключно некеровані ресурси, оскільки керовані об'єкти на момент роботи GC вже можуть бути знищені. У публічному Dispose() передається Dispose(true), що дозволяє безпечно очистити і керовані, і некеровані ресурси.
